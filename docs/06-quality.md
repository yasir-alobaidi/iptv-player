# 06 — Quality, stability & testing

## Stability rules (checked in every review)
- No uncaught exceptions: `FlutterError.onError` and `PlatformDispatcher.instance.onError` log and show a non-fatal toast; errors inside isolates are caught and reported
- Parsers never throw on bad input: they return partial results plus skipped-row reasons (logged and counted in diagnostics)
- Every async operation has a timeout; every retry has a budget and backoff
- Every stream, subscription, timer, and process is disposed by its owner (`ref.onDispose`)
- Bounded resources: image cache (memory 150 MB, disk 500 MB), EPG retention window, rotating logs (5 × 5 MB)
- Every DB migration step has a test
- A file under its final name is always complete: downloads write to `.part` and rename only after verification; the library never modifies files in folders the user added

## Fake receiver (tools/fake_receiver)
`dart run tools/fake_receiver/bin/fake_receiver.dart --port 8010` (Phase 7 decision 8; its README lists what it does like the TV, and its faults)
- A Cast device on 127.0.0.1: Cast v2 over TLS with a test-only certificate, the receiver, media and multizone namespaces, the heartbeat, and a media session whose position runs with the clock. Never advertised on the network: tests and the app add it by address
- Its own hand-written `CastMessage` codec, checked against `protoc --encode`, so a mistake in the app's generated code can't cancel out
- Faults: silent, heartbeat off, dropped or refused connections, a refused LAUNCH, refused LOADs, another app taking the device, the remote's pause, play and Back, raw bytes and JSON to every sender; a slow LAUNCH (`launchDelay`, the TV's 3–6 s)
- **Tests start it in-process** (a path dev-dependency of the app, like the fake provider): `FakeReceiver.start()` on a free port
- **It plays for real** with `FakePlayback(ffprobe:)` (CLI `--ffprobe`), Phase 7 step 5: it fetches what LOAD names as the TV does (HLS polled from the live edge, every new segment checked with ffprobe for codec, height, channels and frames; a continuous stream read from `Range: bytes=0-`; `Origin: https://www.gstatic.com` on every request, an answer without CORS dropped), and its media session follows what arrived: PLAYING, BUFFERING on a stall, IDLE/ERROR, IDLE/FINISHED. `fetches` and `checks` let a test see that picture and sound really came. **Since step 7 it reads a fragmented MP4 as a TV's buffer does** (30 s ahead, again below 10 s, nothing while paused; each fragment's `tfdt` says how far the bytes go), so a relayed file waits on the TV as on a real one: reading as fast as it came hid two relay bugs (ADR-014 step 7)
- Device profiles (CLI `--device`): `FakeDevice.tv4k` (Living Room TV as found), `chromecastHd` (1080p, H.264 only), `tvOnHdLink` (a 4K TV on a 1080p HDMI link: a bare LOAD_FAILED above 1080p)
- **The relay's tests cast the fake panel's channels to it** (`test/data/cast/relay/`: the matrix, the faults, the refusals, the SIGKILL), with the bundled FFmpeg here and the system's 4.4 in CI, which generates its samples before the unit tests for them

## Fake provider (tools/fake_provider)
`dart run tools/fake_provider/bin/server.dart --port 8899 --profile default`
- Xtream endpoints from docs/02 backed by generated data with configurable counts (e.g., 50,000 channels, 30,000 movies, 3,000 series) and quirk toggles (numbers as strings, `info: []`, map vs list episodes, invalid UTF-8)
- `get.php` M3U output and `xmltv.php` (optional gzip, scalable to 300 MB: `?days=`, `?channels=`, `?gzip=1`, `--epg-days`, `--epg-gzip`; 200 channels × 7 days is 27.9 MB). Its quirks, all on in `quirky` and each settable per request: `no_stop`, `bad_date`, `unknown_tz`, `unknown_encoding`, `duplicate_channel`, `orphan_channel`, and `unclosed` (a truncated file — a test's choice, never a profile's)
- Streams: loops generated samples (`ffmpeg -re -stream_loop -1 -i <sample>.mkv -c copy -f mpegts pipe:1`) or serves pre-segmented HLS. Loop an MKV remux of each sample, never the `.ts` itself: looping a TS file with B-frames breaks video timestamps at every wrap (on HEVC 4K about 100 decode errors per wrap and a few-second freeze on the TV; ADR-004 Finding 8). Even from MKV a wrap leaves one short gap (under 0.1 s) and a few decode errors, so tests don't assert on frames around a wrap
- VOD files: movie and episode URLs serve the VOD samples with Range, ETag, Last-Modified, If-Range and HEAD (Phase 5); an open body holds a connection slot, and a new request for the same file takes over the open one, as a player's seek needs on a one-connection panel. `vod_as_hls` serves them as HLS VOD playlists of 4 s TS segments under `/vodhls/` (cut once with ffmpeg; each segment holds a slot while it is sent) and `size_mb` pads a sample to any size with filler made as it is sent (`fakePaddingByte`), for download benchmarks (Phase 8). `If-Range` is checked before the range, as HTTP has it: a validator that doesn't match is the whole file, even for a range past the end
- Artwork: posters, logos, backdrops and episode stills at the sizes real panels link to (600 × 900, 256, 1280 × 720, 500 × 281), a few generated PNGs per kind served under every item's name from the panel's own `/art/…` on the host the client used, so the app's image cache is exercised end to end
- Fault injection per profile or query: `drop_after_s`, `stall_after_s`, `slow_start_ms`, `http_status` (401/403/404/429/500), `max_connections`, `redirect_with_expiring_token`, `codec_switch_after_s`, `cut_after_s`; for VOD files `ignore_range`, `drop_after_bytes`, `throttle_kbps`, `change_etag` (new validators on every answer), `wrong_content_length` (4 KiB past the body), `size_mb`, `vod_as_hls`
- Admin endpoint to change faults at runtime during integration tests (`POST /admin/faults`); **any fault can also be set per request as a query parameter** (`/live/test/test/7.ts?drop_after_s=5`), so one test can fault one stream. Live-stream faults as built (Phase 3): `drop_after_s` ends the body; `stall_after_s` stops the media but sends a 188-byte MPEG-TS null packet each second, so a client that gives up is noticed and its slot freed; `slow_start_ms` delays the answer; `http_status` answers 401/403/404/429 (`Retry-After: 1`)/5xx; `max_connections` refuses with 403 `MAX_CONNECTIONS_REACHED`; `redirect_with_expiring_token` 302s to a `?token=` that gets 403 `TOKEN_EXPIRED` after 10 s; `codec_switch_after_s` swaps to an HEVC (or H.264) loop inside the same body; `cut_after_s` stops the body with no last chunk and closes the connection, which lavf reads as a cut and reconnects by itself, unlike the clean end `drop_after_s` writes
- Live HLS: `/live/u/p/<id>.m3u8` starts one ffmpeg per channel writing 2 s segments (6 in the playlist) served from `/hls/<id>/`, shared by every viewer, holding one connection slot, stopped 20 s after the last playlist request
- **Tests start it in-process.** It is a path dev-dependency of the app (`fake_provider: {path: tools/fake_provider}`), so a test calls `FakeProviderServer.start(state: …, port: 0)` and gets a free port. Two traps: flutter_test's binding answers every `HttpClient` request with a 400, so a test that talks to a real server sets `HttpOverrides.global = null` in `setUpAll`; and an in-process server shares the test's isolate, so **a timing or UI-jank measurement must run the server as a separate process** (`dart run tools/fake_provider/bin/server.dart --profile large`), or the server's own JSON encoding shows up as the client's jank

## Media samples (tools/media_samples/generate.sh)
Synthetic sources only (`testsrc2`, `smptehdbars`, `sine`):
h264_1080p50_aac.ts · h264_1080p25_ac3.ts · h264_1080i50_mp2.ts (interlaced) · hevc_2160p25_eac3.ts · hevc_1080p50_aac.ts · mpeg2_576i25_mp2.ts · codec_switch_h264_720p_to_1080p.ts · vod_h264_aac_10min.mp4 · vod_hevc_eac3_subs.mkv · vod_h264_ac3_10min.mkv + vod_h264_ac3_10min.en.srt
Live samples are 30–120 s long and the fake provider loops them; VOD samples are 10 minutes.
`tools/media_samples/library_tree.sh <dir> <count>` builds a fake library (movies, episodes, junk release names, subtitles, nested seasons) from short low-resolution clips; fictional names only. As built (Phase 8 step 2): every video is a copy of one of two 2-second clips (about 40 KB) with its own number appended, so sizes and quick hashes differ (an ffmpeg run per file would take minutes for 5,000; the copies take 15 s); one unsorted video in 25 carries an embedded title tag; the junk to skip comes on top of `count` (samples, trailers, featurettes, a hidden folder, a `.mkv.part`, a file under the minimum, `.nfo` files); `<dir>/.manifest.tsv` (hidden, so the scanner skips it) says what the scanner should make of each file. Tests lower the scanner's 20 MB minimum file size.

## Performance budgets (profile mode, dev laptop)
Measured by tests tagged `benchmark`, which are skipped unless run with `flutter test --tags benchmark --run-skipped` (timings on shared CI runners are noise); the numbers go in docs/progress.md. The sync budget: `test/data/sync/sync_benchmark_test.dart`, with the fake provider in its own process. The XMLTV import: `test/data/sync/epg_import_benchmark_test.dart` (the `large` catalogue synced, then a ~300 MB guide from the fake provider in its own process, end to end). The Guide grid's scroll: `integration_test/guide_scroll_test.dart` with `flutter drive --profile -d linux --driver=test_driver/integration_test.dart`, on the real display (under xvfb the software rasterizer competes with the app for the CPU and the numbers wander run to run); it reports each kind of scroll apart — flings, the wheel down, the wheel sideways, →, PageDown. The poster grid's scroll and the decoded pictures' memory: `integration_test/poster_grid_scroll_test.dart`, the same way (the `large` catalogue's 30,000 movies, each poster through the app's own picture cache; flings, the wheel, ↓, PageDown, End and Home, then the whole grid top to bottom and the image cache after it). The cold start: `test/app/cold_start_benchmark_test.dart` launches the app's own profile build (`flutter build linux --profile` first) five times on one data folder holding the synced `large` catalogue, history in every Home row and Home's pictures cached, and times each launch from `Process.start` to the line Home logs on its first frame with its rows (`LaunchMark`, by the line's own timestamp); the launched app gets a D-Bus address that leads nowhere, so it can't reach the keyring.

## CI (GitHub Actions)
Matrix ubuntu-22.04 + windows-latest (`.github/workflows/ci.yml`): `flutter pub get` **and `dart pub get --directory=tools/fake_provider`, without which the root `flutter analyze` cannot resolve that package's imports** → build_runner (fail on diff; `core.autocrlf false` is set before checkout so Windows does not fail on line endings) → `flutter analyze` (`analysis_options.yaml` excludes `third_party/**` and `spike/**`) → `dart format --set-exit-if-changed lib test integration_test tools` (not `.`: vendored upstream code isn't formatted to our settings) → `flutter test` → `flutter build linux|windows --release`. Linux job also runs integration tests against the fake provider under xvfb, one file per run, after generating the media samples the player tests need with Ubuntu's ffmpeg (live samples 30 s, VOD samples 120 s — shorter than this laptop's 600 s, which once hid a bug: ADR-013), and with `IPTV_PLAYER_VIDEO=0` (no GPU: mpv plays with no picture). Upload release builds as CI artifacts.

**Failures are named on the public run page** (the job log needs rights on the repository): each failed test, unit or integration, becomes an annotation with its error — the `flutter test --file-reporter json:<file>` report read by `tools/ci/failed_tests.dart`, which takes a widget test's printed exception where the error event only points to it. Read them with `curl https://api.github.com/repos/<owner>/iptv-player/check-runs/<job id>/annotations`.

## Definition of done (every feature)
1. Spec behavior implemented, including loading/empty/error/offline states
2. Fully usable by keyboard with visible focus
3. Tests at the right layers, all green
4. No analyzer warnings; formatted
5. Logs redacted; no secrets anywhere
6. docs/progress.md updated
